# Artifact Model

Use one canonical owner for durable knowledge.

- `AGENTS.md`: thin navigation and durable agent rules.
- project context: repository orientation for agents.
- `PRODUCT.md`: durable product purpose, users, domain language and product constraints.
- `DESIGN.md`: durable visual and interaction system.
- ADR: consequential architecture decision and tradeoffs.
- SPEC: what behavior must hold.
- PLAN: how the current change will be implemented.
- ACCEPTANCE: observable evidence that the behavior works.
- HANDOFF: exact current execution state.

Avoid duplicating facts already authoritative in manifests, task runners, source code, or another canonical artifact.
