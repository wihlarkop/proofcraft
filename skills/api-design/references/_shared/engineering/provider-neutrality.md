# Provider Neutrality

Resolve technology in this order:

`task -> concern -> capability -> existing project technology -> available specialist -> provider`

Installed is not selected. Available is not appropriate. Existing accepted architecture wins unless intentionally changed. Generic capabilities should describe required semantics rather than named vendors.

Provider integrations may enhance execution but must not choose the project's database, cloud, IaC system, queue, cache, model provider, or observability stack as a routing side effect.
