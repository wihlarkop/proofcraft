# Specification Contract

A specification states WHAT must be true, not HOW to implement it.

Prefer:

- problem/user outcome;
- behavior and invariants;
- state/lifecycle semantics where material;
- failure behavior;
- compatibility expectations;
- observable acceptance criteria;
- out of scope and unresolved decisions.

Avoid line-by-line implementation instructions, invented file paths, or dependency choices that have not been decided.
